Transitioning your AIDA GNN surrogate model from the **M4 mesh** (2,562 nodes) to the higher-resolution **M6 mesh** (40,962 nodes) touches multiple parts of your pipeline—from graph operators and memory allocation to configuration files and feature statistics.

Here is a comprehensive checklist of everything you need to update:

---

### 1. Update Configuration Files (`configs/config.yaml`)

Update mesh dimensions and file path references to target M6:

```yaml
mesh:
  name: "icosahedral_m6"
  num_nodes: 40962                     # Updated from 2562 (M4) -> 40962 (M6)
  num_levels: 32
  edge_index_path: "../graph/graph-grid/icosahedral_edge_index_m6.pt"

data:
  zarr_path: "../data/icosahedral_m6_logstate.zarr"  # Updated to your new M6 Zarr
  obs_dir: "../data/all_NNJA_data_2024"

training:
  batch_size: 1                        # REDUCE batch size (M6 node count increased 16x)
  accum_steps: 8                       # Increase gradient accumulation to maintain effective batch size
  lr: 0.0001                           # Scale learning rate slightly down for larger graph topologies

```

> ⚠️ **Memory Warning:** Because M6 has **16x more nodes** per level, GPU VRAM usage will scale dramatically. Reduce `batch_size` (e.g., from `4` down to `1` or `2`) and increase `accum_steps` to avoid CUDA Out-Of-Memory (OOM) errors.

1. **Delete old cached M4 operator files** (if any exist in `../graph/` or `/tmp/`).

3. Verify that the output sparse COO/CSR matrix sizes match `(40962, 40962)`.

### 3. Verify Static Surface Topography & 3D Height Extrapolation (`models/dataset.py`)

Update the channel statistics buffers in `AIDASurrogateLoss` inside `models/loss.py`:
